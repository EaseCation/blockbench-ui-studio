# 编组整理修复与验证（0.8.4）

## 实测根因

在隔离Blockbench 5.2.1 Web宿主，以两个有颜色的Image构造最小复现稿：

1. 原生视口框选只选中内容Cube，大纲逻辑选区却显示Image。执行原生编组后，Cube从Image容器中搬走，两个Image均进入“内容载体缺失或已移出”暂停状态。拖动无法保持预期整体关系。
2. 选中Image执行原生解除编组，宿主拆除内部Group；场景回读仍无条件过滤内容Cube，导致两个Image被认定为删除，贴图由2张变成0张。
3. 在逻辑层解除Frame时，如果先删除原生容器再重新挂接子项，宿主递归删除会破坏存活子项。删除顺序必须后移。
4. Undo恢复了原生对象，但逻辑选区未重新读取；恢复的Frame没有成为当前操作对象。
5. 菜单打开后与快捷键共用的上下文条件会拒绝执行；菜单执行和键盘捕获需区分。

## 实现边界

- Domain增加纯数据groupNodes/ungroupNodes。Frame解除时提升子项；Image解除时保留自身内容并释放逻辑子项。递归解组移除所选范围内的Frame，保留全部Image及其像素/来源参数。
- 编组支持单选、多选及跨自由容器选择，找到公共祖先并保持所选项内部顺序、世界边界。百分比保留系数并重算像素项；根节点无百分比参照，转为固定尺寸和位置。
- Stack连续流式子项可编组；向Stack直接拆回或不连续流式编组会明确要求先关闭父级自动布局。图层整体化后，不保证维持与未选中图层交错的显示层级。
- 通过原生Action.use事件路由编组菜单，无原型覆盖；普通项目/卸载恢复原行为。
- 仍使用原生框选框。松手前识别完整包围的Frame，并把逻辑选区归一到原生容器，使框选、菜单、后续拖动和选择历史一致。
- 场景回读识别“容器消失但内容Cube存活”，保留逻辑ID和素材；独立修改UV/几何仍被保护。原生应用先安置存活子项，再删除旧容器。编组后选择与编辑同一次Undo；重做/撤销回读原生选区。

## 可重复验收

`tests/host/grouping.spec.ts`使用合成测试稿，包括多层Frame、Image嵌套、原生绘画分层、64×32高清贴图在30×20显示、九宫格、百分比定位及文字。UI单插件和双插件均执行真实鼠标框选、全部解组、原生菜单编组、视口拖动、快捷键解除、Undo/Redo、再编组及保存重开。断言内容Cube/Texture UUID、PNG、UV、绘画层状态和文字配方保持，子项跟随移动，单次操作一条编辑历史。

另覆盖原生代码直接拆除所有Group、叶子Image解组无操作、普通项目/卸载、工具菜单与创建Frame快捷键。单元测试覆盖公共祖先/内部顺序、百分比/锚点、隐藏状态、Stack限制、锁定/暂停与提交失败回滚。

怪物洞原稿只读加载到独立副本：176个Image、70处文字，递归解组后数目相同；对6个元素编组并移动，全部图片、贴图UUID、文字和像素保留，三个编辑步骤逐次撤销后恢复原边界，无暂停。没有改写用户的原设计文件。

测试稿、前后截图和复测记录随交付提供。自动化使用真实浏览器鼠标/键盘事件，不等同于人工Mac触摸板手感验收。

## 使用

- Command/Ctrl+G：选区组成自由Frame。
- Command/Ctrl+Option/Alt+G：从选区创建Frame。
- Command/Ctrl+Shift+G：解除一层。
- 工具或右键菜单 → UI：解除全部编组：递归整理。

仅UI Studio需要更新至0.8.4，文字插件继续使用0.2.2。原结构无须重新转换。此修复阻止后续操作丢失，不会凭空恢复旧版本操作后已经删除的像素；已有损坏现场应先撤销或打开备份，再用新版整理。

测试基础设施同时固定宿主启动新闻/插件统计响应，避免远端连接关闭引发无关的jQuery拒绝；文字历史测试等待源图/字体异步恢复完成后再执行下一条命令。没有屏蔽插件自身异常。

验证：UI Studio类型、边界、构建、格式及76项单元测试通过；完整宿主104项通过。文字插件完整联动宿主22项通过。
