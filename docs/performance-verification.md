# 复杂项目编辑停顿调查与修复

2026-09-23，UI Studio 0.8.1→0.8.2，BBModel Text Component 0.2.0→0.2.1。

## 复现与定位

使用同一份282逻辑节点、176 Image、70可编辑文字的模型，在独立Blockbench 5.2.1 Web宿主/Chrome/SwiftShader中测量。保留原版bundle作为对照，使用相同输入及浏览器启动选项；未改用户应用配置。计时包括实际原生Undo事务，不以鼠标拖动中的临时预览代替松手提交。

CPU采样和阶段计时确认：布局约1ms，主要阻塞来自撤销阶段。UI属性的Property.condition在每个Group快照构造/reset/copy时反复扫描全部bindings；临时Group有UUID而没有角色标记，简单用标记查找仍会退回全树扫描。文字插件还对每个文字Cube反复深拷贝完整字体及RGBA数组；70个传输payload的JSON展开量约442MB，普通移动会复制这些重复数据。

## 修复

- PropertyBridge用绑定表引用索引原生UUID，支持真实对象及无标记的撤销副本；当前文档更换时重建。属性回填一次计算选区摘要及对象表。
- 文字传输注册为宿主instance Property，字体和像素使用不可变快照，未变化的PNG/字体复用原对象；文字变化替换快照，旧历史保持不变。字体在多个Cube间共享。跨项目原生剪贴板仍携带自足JSON数据。
- payload包含PNG身份，Undo恢复时重用对应快照，避免读取尚未完成异步解码的纹理canvas。文件编译仍剥离传输字段；保存结构与schemaVersion 1不变。
- 保留完整Undo、原生差异保护、原有贴图分辨率和标准Cube/Texture输出；实现限定在插件适配器与注册接口内。

## 同机结果

| 操作                                  | 修改前                | 修改后             |
| ------------------------------------- | --------------------- | ------------------ |
| 真实鼠标松手提交（三次）              | 2761 / 2602 / 1928 ms | 176 / 133 / 119 ms |
| 修改文字（一次）                      | 2173 ms               | 174 ms             |
| 普通位置属性编辑，双插件（三次）      | 2702 / 2277 / 1919 ms | 193 / 125 / 122 ms |
| 普通位置属性编辑，仅UI Studio（三次） | 1207 / 1135 / 1152 ms | 160 / 97 / 97 ms   |

这些是同一测试环境中的对照值，不是所有设备的延迟保证；未做人手Mac触摸板测量。首笔包含冷缓存成本。

## 回归

两个仓库的类型、单元、构建、格式与差异检查。UI宿主新增282节点位置编辑与Undo/Redo停顿回归；文字宿主新增71文字共享资源、历史快照不可变、改字替换像素及Undo恢复；原生跨项目粘贴经过JSON边界验证。文字测试在编辑和撤销之间等待宿主的canvas-to-image上传完成，再验证恢复的RGBA；不把同一JS任务内未完成的宿主图像上传当作编辑完成。

UI Studio的check通过（68项单元测试、类型、依赖边界与构建），完整宿主98项通过；文字插件check通过，原有20项宿主用例及新增1项资源/撤销用例通过（新增用例在等待宿主图像上传后单独复跑）。两个仓库格式和差异检查通过。

不需要迁移或重新生成用户的bbmodel；应同时更新两个插件并重新打开项目。
