# 普通建模与撤销隔离回归

本轮检查使用隔离的 Blockbench 5.2.1 / Chrome 宿主，没有操作用户正在使用的桌面模型。

## 原因与修复边界

旧文字插件 0.2.2 的 `init_edit` 在没有文字时跳过扩充快照，但 `finish_edit` 无条件把全项目元素和纹理加入编辑后快照。由此产生不对称的历史：一次只移动一个 Cube 的操作，编辑前记录 1 个，编辑后记录 3 个。Blockbench 撤销时把另外 2 个视为本次新增并移除；重做的元素快照没有同时保存大纲，重新创建的元素会丢失原父级。

隔离对照中原版、仅 UI Studio 正常，仅文字插件及双插件均复现。问题并非普通模型需要被 UI Studio 理解，而是文字插件扩大了宿主历史的参与范围。

文字插件 0.2.3 将快照参与逻辑移到 `blockbench/native-edits.ts`：

- 宿主拥有原始操作范围与数组；插件不替换它们，也不拦截原生 Undo/Redo。
- 文字参与者描述自己的 Cube 和纹理；事务协调层只成对补充这些内容的编辑前后快照。
- 没有文字的普通操作不扩充元素、纹理或大纲快照。混合项目不把无关普通 Cube/Mesh 加入历史。
- 首次粘贴、最后一个文字的删除、取消编辑及资源存在/缺失状态由同一快照流程处理。
- UI Studio 项目由 UI Studio 协调受管理内容；文字插件独立运行时使用自身协调层，没有新增 UI Studio 依赖。
- 字体查询只读，实际嵌入或导入时才写项目资源。

UI Studio 运行时无需修改，本仓库新增普通模型集成回归。已有旧版本生成的错误撤销记录不会被重写；修复保证更新后创建的编辑记录遵守上述范围约定。

## 覆盖范围

`tests/host/native-modeling.spec.ts` 包含四组插件对照、三种格式的完整编辑链和自由模型 Mesh 验证。模型含嵌套 Group、多个 Cube 及真实纹理；通过原生 Action、SharedActions 与 Undo API 进行操作。

每个操作比较完整父子树、几何、分组变换、UV、纹理内容，并反复 Undo/Redo；完整编辑链再从末尾退回最初状态并重做全部操作。覆盖新增、编组、解组、组复制、换父级、旋转、尺寸修改、UV 编辑、绘画、重命名、删除、取消、UI 项目往返、保存后无插件重开及卸载。

文字仓库另外覆盖无 UI Studio 的普通模型和混合模型：原位加载插件、普通对象旁放文字、文字原生缩放、复制、删除最后一个文字、向已有模型首次粘贴文字，以及取消恢复。验证旧纹理不丢失、新文字纹理独立、字体内嵌、一次 Undo 和实际快照参与者数量。

最终命令与结果记入两个仓库的 `docs/verification.md`。这些测试覆盖上述建模流程，不代表所有第三方插件、动画或全部 Blockbench 格式都已验证。
