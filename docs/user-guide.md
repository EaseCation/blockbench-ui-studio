# UI Studio 使用指南

面向二维界面设计与像素美术的独立 Blockbench 插件。Image 使用原生 Group＋内容 Cube，Frame 使用原生 Group。X/Z 表达布局、Y 高度表达显示层级；内容 Cube 的 Y 厚度为 0，仅顶面使用贴图；未安装插件也能查看标准模型和贴图。

## 安装与开发

要求 Node.js 22+、Blockbench 5.2.1。桌面版和 Web 版使用同一个插件文件。

```sh
npm ci
npm run check
```

在 Blockbench 的 **文件 → 插件 → 从文件加载插件** 中选择 `dist/mcui_studio.js`。然后在开始页 **新建 → 总体 → UI 设计** 中点击 **创建 UI 项目**，也可以双击“UI 设计”直接创建。**工具 → 新建 UI 项目** 入口仍然可用。

“UI 设计”是原生创建入口，项目实际仍保存为通用模型（Generic Model）的 `.bbmodel`，未安装插件的客户端也能打开。

开发时运行 `npm run dev`，重新加载本地插件即可。源仓库不要求放在 Blockbench 目录中；构建也不依赖 Blockbench 源码路径。

## 工作方式

- 新项目以 Frame 画板开始，使用正交顶视图。使用原生工具栏创建 Image、Frame 或导入图片。选中 Image／Frame 时，新建默认放入其内部；右键可新增同级。
- 直接使用原生“大纲”管理图层、排序、换父级、重命名、隐藏和锁定。
- UI 设计的 Figma 编辑布局：大纲在左、属性在右，UV 和纹理默认收起；可手动展开，选择对象不会再次折叠。切换原生交互、进入绘画、切到普通项目或卸载时恢复原布局；Figma 内的 2D／3D 切换保持侧栏位置。
- 2D 编辑时大纲工具栏优先显示新增 Frame、Image；原生新增元素／分组、高级大纲开关和“查看／隐藏原生结构”收进右侧三个点。搜索和计数保留；3D、绘画和普通项目恢复原版排列，不改写工具栏自定义顺序。
- 初次选择 UI 对象打开原生“元素”；之后记住用户选择的“元素／UI 布局／UI 内容”标签。内容页选到 Frame 时临时回退布局，再选 Image 会恢复内容偏好。
- “UI 布局”按自身尺寸、子项排列、自身定位分组；“UI 内容”按素材、填充、描边、尺寸变化分组。继续使用原生附加标签和注册式表单控件。
- 元素页保留原生字段说明；组合控件使用就近单位、摘要和悬停提示。折叠不会停用规则，已设置的约束与非对称边距始终有摘要。
- 宽高支持 `80px`、`100% - 16px`、`fill`、`hug`；位置支持 `16px`、`-8px`、`50% - 8px`，在锚点结果上叠加。
- 百分比参照父级对应尺寸；根节点没有父级，不能使用父级百分比。自动布局中的流式子项位置由父级控制。
- 表达式输入按 Enter 或失焦提交，Escape 取消；多选时只修改输入的轴，不把其他轴统一覆盖。
- “UI 内容”可快捷设置背景纯色／双色线性渐变、角度、颜色透明度及向内描边。描边粗细以贴图像素计；填充在原图下方，描边在上方。
- 点击“合成为可绘制像素”合并当前效果，可一次撤销，或使用“恢复原始来源”。带外观时绘画按钮标为“合成后绘画”；双击行为相同。颜色选择器内调整暂不改变模型，关闭确认最终颜色一次提交；取消或 Escape 不写入。
- “尺寸变化 → 保留贴图”固定贴图尺寸、UV 和 UV 尺寸，W/H 只改变几何显示大小；导入图片默认采用此策略。修改适配模式或源图仍会重新生成固定分辨率的贴图。
- “尺寸变化”可选跟随显示尺寸；手绘直接选择扩展画布或重采样，图片使用当前适配模式重新生成。K 在扩展画布与保留分辨率之间切换。
- 选中 UI 素材自动切到对应贴图和顶面 UV，无需先进入绘画模式。
- UI 顶视图隐藏中心网格、坐标轴、原点标记和方向控件；每个 UI 像素达到约 8 屏幕像素后淡入全视窗像素网格。透视与卸载恢复原生辅助，不改动用户的网格设置；辅助网格不进入原生截图。
- 图片支持 Stretch、Fit、Fill、Crop 和原始像素。单选图片层时粘贴替换内容，其他情况下创建图层；“粘贴为新图层”始终新建。
- 九宫格面板配置四边边距和拉伸／平铺模式。成品始终是一张实际目标尺寸纹理和一个 Cube。
- 普通图层双击进入原生绘画。图片／九宫格双击编辑源图，使用原生绘画工具栏或“工具”菜单中的“应用源图到 UI”提交，或“取消源图编辑”。直接润色成品可先“转为绘画图层”。
- Frame 可横向／纵向自动排列，支持 padding、gap、对齐、固定尺寸、Fill、Hug、父级百分比加减像素。绝对定位子项不参与排列和 Hug。
- 使用原生保存和原生截图；项目不依赖自定义渲染器。

## 图形化布局工作流

选择 Frame 后进入“UI 布局”：

1. **W/H 数值与模式同排**：固定、填充、包裹或百分比表达式可以直接在布局页编辑，元素页保持同步；长表达式自动改为两行以便完整输入。根节点／尺寸循环对应的选项禁用并说明原因。
2. **自由／横向／纵向**直接切换。对齐图与间距并排，Auto 表示两端分布，旁边的数值是最小间距；只保留交叉轴三个有效对齐方向。
3. **内边距默认水平／垂直**；点击“四边”分别编辑上右下左。非对称值显示混合，展开不改数值；“联动四边”只影响下一次输入。自由 Frame 的内边距仍可影响 Fill/Hug，保持可见。
4. **定位预设**将父锚点与自身锚点一起设到九点位置；保留百分比与像素偏移。独立锚点展开后分别编辑；非相同锚点显示自定义。
5. **尺寸限制**是一条带当前值摘要的展开行，展开后最小 W/H 与最大 W/H 各一行；折叠不产生 Undo、不清除限制。
6. 多选各字段显示混合值；只改输入的轴或属性。Stack 的流式子项位置禁用，需显式切到绝对定位；自由 Frame 的子项可选择是否计入父级包裹。

Image 的“UI 内容”默认只展示相关属性。填充与描边未启用时显示“＋ 添加”，启用后颜色与参数同排；渐变终点与角度就近展开。素材组提供绘画／源图、导入替换和已有来源恢复。图片只在 Crop 下展示倍率与偏移，Stretch 隐藏不生效的锚点。九宫格可从“编辑切片”查看源图切线与生成结果；数值修改只在确认后提交，暂不支持直接拖动切线。

“尺寸变化”同时显示显示尺寸与贴图尺寸。保留贴图时只改几何，比例不同会提示拉伸；九宫格固定按目标尺寸生成。源图缩略图不包含后加的填充与描边。

选择同父级的多个素材，点击大纲工具栏或右键菜单中的 **“将所选项组成自动布局”**，自动建立 Frame、按选区位置推断横向／纵向和平均间距，并打开布局标签。子项保持当前宽高，Frame 包裹内容；重叠的间距按 0 处理，排列会统一。整个操作可以一次撤销。

切回自由布局时保留子项位置；由流式改为绝对定位也保留位置。退出依赖布局时将 Fill 尺寸固定为当前结果，避免尺寸突然改变。横纵方向切换时保持屏幕上的对齐方向（两端分布保持沿主轴分布）。九点图支持方向键；分段按钮可通过 Tab 聚焦、Enter 或空格操作。

## Image 嵌套与视口放入

Image 可以包含 Image 和 Frame；Frame 支持自由布局（panel）或横向／纵向自动布局（stack_panel），自身不绘制背景、描边或贴图。需要背景时使用 Image 包含 Frame。

大纲中 Image 显示为可展开的图像节点，其内部的成品 Cube 默认隐藏。点击“查看／隐藏原生结构”可查看完整 Group＋Cube。隐藏仅影响大纲，不影响画面。拖到行中央放入容器，前后位置调整同级排序，支持多选和原生撤销。

2D 顶视图的 UI 选择工具中，悬停显示浅色轮廓。Image 按矩形命中；Frame 的边框和名称可点击，其内部空白仍可开始框选。仅根级 Frame 左上角常驻显示名称；嵌套 Frame 使用边框与控制点，不显示左上角名称。名称、轮廓和目标提示不进入原生截图。

视口工具栏的“自动放入”默认开启并记住本机选择。拖动时显示“放入：名称”；Stack 显示插入线。松手后一次提交移动、父级变化和布局。关闭开关后只移动位置／原父级内排序，不改变父级；大纲拖入仍然可用。没有合法放入目标时保留原父级。Escape、失焦、模式或项目切换取消拖动。

移入自由容器保留世界位置与显示尺寸，百分比表达式保留系数并调整像素分量；Fill 必要时转为固定尺寸。移入 Stack 则参与目标的自动排列。

选中 Image 会自动同步自身贴图；绘画时只选中自己的内容 Cube，退出绘画回到 Image。替换图片保留子元素，另提供“粘贴图片为子图层”。多张图片导入同一目标，不逐张形成嵌套链。

## 整理图层：编组与解除

在二维Figma模式下，普通框选会把命中的内部图层归并到当前范围的外层Frame/Image，不需要完全框住该Frame。从容器内部空白起手时在其内部选择，越出容器后范围向外扩大；跨画板选择保持在共同外层，不同时选择父层和子层。

按住 **Command（Mac）／Ctrl（Windows）＋拖拽** 直接框选内部图层，支持从已绘制的Image上起手。拖动过程中按下或松开该键会立即切换结果；Shift可追加选区，深选会用新命中的子项替换原选区中的祖先。大纲和视口在拖动中保持一致。Escape、失焦、切换项目/工具/模式或打开弹窗取消框选，恢复起手前选区。若开启Blockbench的选择撤销，完成一次框选只记录一条选择历史。

- **Command/Ctrl+G**：把选区组成自由Frame，自动选择新Frame，可直接拖动边框来整体移动；根级 Frame 也可拖动名称。
- **Command/Ctrl+Option/Alt+G**：从选区创建Frame，行为同上。
- **Command/Ctrl+Shift+G**：解除一层编组。
- 工具菜单或图层右键中的 **“UI：解除全部编组”**：递归解除选中的Frame/Image内的分组，再框选需要的内容重新编组。

Image自身不是可丢弃的普通组。解除带子项的Image时，其底色/图片/文字保留为原Image，子项提升到同级；对叶子Image解除编组不会删除它。解除全部编组会保留所有Image，移除所选范围的Frame。原生编组/解除菜单也接入相同逻辑；原生“新增组”在单选时保留向内部新增Frame的行为，用Command/Ctrl+G包裹单选。

重新组织保持世界边界与所选项内部顺序；百分比会调整像素项，提升为根节点时改用固定尺寸/位置。整个编组作为一个绘制层级，不保证跨越其它未选中图层后仍能维持原来的交错层级。Stack中连续流式子项可直接编组；拆回Stack或编组不连续流时，应先关闭父级自动布局。每次操作对应一次Undo。

## 场景拖拽绘制（A / R）

视口工具栏新增“绘制 Frame”（A）和“绘制 Image”（R）。在 UI 设计的二维 Figma 交互模式下，选择工具后拖拽画出尺寸；松手一次创建、选中新元素并返回 UI 选择。Image 初始为对应尺寸的透明绘画贴图，Frame 初始为自由布局。

- Shift：正方形；Option/Alt：以按下点为中心；可以组合使用。边界落在整数 UI 像素上。
- 绘制中按住 Space 移动绘制框，松开后继续调整尺寸。未开始绘制时，Space＋拖动或中键仍用于平移视图。
- “自动放入”开启时，按下点命中的最深可编辑 Image／Frame 为父级，整个手势保持该父级；关闭时创建根级元素。
- Stack 中会显示插入线和虚线位置预览；松手后保持绘制宽高，位置由自动布局决定。
- 预览期间不创建模型、不分配贴图、不产生 Undo；完成后一次撤销。点一下或视口外松手不创建元素。
- Escape 取消当前绘制，再按一次返回选择；V 返回选择；右键取消并返回选择。失焦、指针取消、切换工具／项目／模式、弹窗打开都会取消未提交绘制。
- 绘制中暂缓滚轮导航，避免尺寸因相机变化跳动。删除或撤销快捷键先取消绘制，不误操作原选区。
- A/R 使用原生快捷键注册，可在设置中修改。R 仅在上述 UI 场景优先用于绘制 Image，原生交互、透视和其他项目保留宿主快捷键行为；输入文字或操作弹窗时不抢键。

## 数值微调与拖拽

元素、UI 布局、UI 内容的尺寸／坐标和数值控件支持 **↑ 加 1、↓ 减 1**，即时应用。宽高、位置、尺寸限制、间距、四边内边距、描边、渐变角度、裁切倍率／偏移和九宫格边距都使用相同方式。图片／九宫格预览窗口内先修改草稿，点击确认后应用。

按住 **Option（Mac）／Alt（Windows）拖动输入框**，或直接拖动 W/H、X/Y 等旁边的标签，可左右调整数值。默认每屏幕像素对应 1 单位；向上移超过约 40px 加速到 2×，向下移超过约 40/80px 减速到 ½×/¼×，底部显示当前档位。一次拖动只产生一条 Undo，Escape、失焦、指针取消、模式／项目切换取消本次调整。普通拖动仍用于选择输入文字；当前采用指针捕获，不提供光标越过屏幕边缘后的无限拖动。

百分比保持不变，例如 `100% - 16px` 按 ↑ 变为 `100% - 15px`。固定尺寸最低 1px，其余最小值沿用字段约束；Fill/Hug 需先切换为具体尺寸再微调。空白／混合值需先输入数值，避免不经确认统一多个图层的不同参数。

## 键盘工作流

在 Figma 二维编辑模式下，**Shift+A** 给选中的 Frame 原地启用自动布局，或把同级选区组成自动布局；再次按下不会重复套 Frame。**Option/Alt+Shift+A** 关闭自动布局并保持当前边界。

**Shift+1** 查看全部，**Shift+2** 聚焦选区，仅改变相机。点击 UI 布局／内容面板后，Command/Ctrl+D 复制与复制粘贴、删除仍作用于逻辑图层；输入框保留原生文字编辑操作。

新增命令可在「设置 → 快捷键」重绑定，也可在「工具」菜单查找。输入框、颜色弹层、对话框、绘画、原生交互、透视和拖拽期间不执行这些新快捷键。完整对照与后续建议见 [快捷键调研](shortcuts.md)。

## Figma 风格操作

| 操作                  | 效果                               |
| --------------------- | ---------------------------------- |
| 左键拖动元素          | 移动图层／自动布局中排序           |
| 空白处左键拖动        | 框选                               |
| Shift 点击／框选      | 切换选择／添加选择                 |
| 拖动八点框            | 调整尺寸                           |
| Shift 拖动控制点      | 等比并保留贴图分辨率（九宫格除外） |
| Option 拖动控制点     | 中心对称                           |
| Option 悬停其他元素   | 测量像素距离                       |
| 中键或空格＋拖动      | 平移                               |
| 触摸板双指滑动        | 平移                               |
| 触摸板捏合／Ctrl 滚轮 | 围绕指针缩放视图                   |
| 双击                  | 原生绘画／源图编辑                 |
| Escape                | 取消当前拖动                       |

“交互风格”和“2D／3D 视图”可独立切换。透视视图和原生交互使用 Blockbench 的导航方式。绘画期间保留原生画笔修饰键。

## 兼容性

原生客户端可以显示、修改、绘画和截图最后保存的内容。响应式布局、图片适配、源图编辑和九宫格重新生成需要插件。

插件规则保存在原生 `.bbmodel` 的 `unhandled_root_fields.mcui_studio` 字段，引用稳定 UUID；成品纹理内嵌。无插件保存后重开时检测几何或贴图差异，保留当前结果并暂停有冲突的规则。可选择采用当前结果或按规则重新生成。

开发阶段数据结构仍为 version 1，但仅接受本轮 Image／Frame 定义，不加载或迁移旧插件数据。请使用新建项目。普通 Blockbench 仍能显示现有文件中的原生模型。

项目使用 Generic Model 格式。转换为其他模型格式可能清除规则；不把这种格式转换视为可恢复的 UI 编辑工作流。

支持范围为静态像素 UI，不包含完整 Figma、游戏运行时绑定、动态文字、复杂网格或实时协作。原生透明度与截图抗锯齿行为仍由 Blockbench 决定。

## 验证

```sh
npm test                 # 独立业务与像素测试
npm run typecheck        # 含无 DOM 的业务内核配置
npm run check:boundaries # 自动检查宿主依赖隔离
npm run test:host        # 真实 Blockbench 页面集成测试
```

宿主测试要求 `.cache/blockbench` 是已构建 Web 版的测试副本，或用 `MCUI_HOST_DIR` 指向测试宿主。默认使用系统 Chrome，无需用户浏览器配置目录。详见 `docs/testing.md`。

设计、数据和适配策略见 `docs/implementation-plan.md` 与 `docs/architecture.md`。

### 可编辑文字（整合构建）

同时加载 BBModel Text Component v0.2.1 后，使用大纲「添加文字」创建文字 Image；双击进入实时文字编辑器，或在原生「文字」标签修改排版。UI 布局继续管理宽高和定位，支持百分比宽度、自动换行高度和 Stack 排列。文字内容为普通零厚度 Cube 和内嵌 PNG，卸载文字插件后仍可显示、移动和缩放成品。该能力使用 `Blockbench.mcuiStudio.contents.version === 1` 的独立扩展接口。

## AI 直接编辑设计文件

仓库内提供 [ui-studio-bbmodel 技能](../skills/ui-studio-bbmodel/SKILL.md)，指导 AI 创建、提取、编辑及验证 UI Studio 文件。配套 CLI 使用独立无头宿主生成标准 bbmodel 与 PNG 预览，不需要操作用户的桌面会话。

```sh
npm run ui:file -- build skills/ui-studio-bbmodel/assets/example.design.json --out work/example.bbmodel --preview work/example.png
npm run ui:file -- inspect work/example.bbmodel
npm run ui:file -- extract work/example.bbmodel --out work/edit.design.json
npm run ui:file -- build work/edit.design.json --base work/example.bbmodel --out work/edited.bbmodel
npm run ui:file -- validate work/edited.bbmodel
```

需要当前仓库依赖、系统 Chrome 和构建好的测试宿主；详情见技能环境说明。设计描述是完整目标树，修改文件时保留 ID 并使用 `--base`，避免无意删除未列出的图层。加载实际文字插件并提供内嵌字体后可创建和编辑文字；没有 provider 时仅保留未修改的既有文字成品。

AI 文件工具也支持未使用 UI Studio 的原生平面 UI 显式转换，以及通过本地 BBModel Text Component 插件生成可编辑文字。转换需明确顶视方向、缺失字体替代与需压平的三维 Group；成品仍为标准 Cube/Group/Texture。详见 [AI Skill](../skills/ui-studio-bbmodel/SKILL.md)、[原生 UI 转换](../skills/ui-studio-bbmodel/references/legacy-conversion.md) 与 [文字内容](../skills/ui-studio-bbmodel/references/text-content.md)。集成回归可用 `MCUI_TEXT_PLUGIN=/path/to/bbmodel-text-component.js` 指定文字插件 bundle，默认探测同级文字插件仓库。
