# 基岩版尺寸规则与编辑方式

2026-09-24 核对 [Bedrock Wiki Layout](https://wiki.bedrock.dev/json-ui/json-ui-documentation#layout)、[Intro to JSON UI](https://wiki.bedrock.dev/json-ui/json-ui-intro) 和 [原版 ui_common.json](https://github.com/ZtechNetwork/MCBVanillaResourcePack/blob/master/ui/ui_common.json)。`tts_activate_sibling` 的注释明确称 `%sm` 为 sibling max；Wiki 的标题示例用 `%sm + 30px/6px` 让背景跟随文字，并用 `%cm` 计算外框。

## 尺寸参照

| 输入      | 含义                         | 示例                                       |
| --------- | ---------------------------- | ------------------------------------------ |
| 数字 / px | UI 像素                      | `32`、`32px`                               |
| %         | 父级同一轴的尺寸             | W 的 `50%` 参照父宽，H 参照父高            |
| %x        | 自身宽度                     | W=80px，H=`50%x` 得到 40px 高              |
| %y        | 自身高度                     | H=40px，W=`200%y` 得到 80px 宽             |
| %c        | 直接子项该轴尺寸之和         | `100%c + 8px`                              |
| %cm       | 最大可见直接子项的该轴尺寸   | `100%cm + 8px`                             |
| %sm       | 其他同级元素该轴尺寸的最大值 | `100%sm + 6px`                             |
| default   | 默认父级同轴 100%            | `default`                                  |
| fill      | 父级剩余可用空间             | Stack 主轴扣除固定子项、间距、内边距后分配 |

Image 和 Frame 都支持这些参照。Image 的原生内容 Cube 不计为子项。`%c/%cm` 统计尺寸，不把位置偏移当成尺寸，也不隐式加插件的 gap/padding。`%x/%y` 是自身轴；W 引用 `%x`、H 引用 `%y` 通常形成自引用。

Wiki 明确限定 `%cm` 为可见子项，但未逐条详述 `%c/%sm` 对可见性、同级互依赖的求值边界。本插件采用可复现的静态解释：`%c` 包含所有直接逻辑子项，`%sm` 包含自身以外同级，二者保留隐藏项的尺寸；绝对子项也可参与尺寸参照。`ignored`、工厂及运行时绑定没有被伪装成已实现的尺寸能力。

## 两种编辑方式

在 **UI 布局 → 自身尺寸** 旁选择“组合／表达式”。默认表达式模式延续现有 W/H 输入；选择只作为本机偏好保存，不修改设计或 Undo。

组合模式选择参照来源，输入比例和像素偏移，需要更多项时点击“+ 参照项”。表达式模式直接输入 `100%cm + 8px`。两种方式共享同一份规则，没有“输入百分比后被强行改成另一种类型”的步骤。

解析器接受十进制数、空白和加减项，并把相同参照合并；本插件另外支持 `50% + 25%y - 8px` 这样的多参照线性组合。Wiki 示例主要展示单一百分比参照±像素，多参照组合属于插件创作能力，不据此声称每个游戏版本的原生尺寸字符串解析器都接受同样组合。当前没有游戏资源导出。

无法解析的输入即时红框；循环依赖、缺少父级、矛盾约束或画布过大等无法应用的规则在提交时标红。草稿保留，模型使用上一次有效结果，Escape 恢复。`$变量`、绑定表达式、括号、乘除和 JavaScript 不作为静态尺寸字符串执行。

新节点最小尺寸默认为 0。0 可以折叠图像内容，原贴图保留；恢复正尺寸时重新显示。计算出的负值受最小尺寸约束。已有文件中显式保存的 min/max 保留，因此旧节点的最小值 1 仍会限制结果。画布贴图仍至少 1×1，九宫格的非零尺寸仍受角区限制。

根画板没有隐式游戏屏幕作为父级，非零父百分比、default、fill 需要实际父容器。根画板可使用像素、子项参照或合法的自身跨轴参照。检测到依赖循环会拒绝应用，不迭代猜测客户端的循环布局结果。

## 保留的插件扩展

`hug` 保留现有设计语义：Image 使用素材原尺寸，Frame 使用流式布局内容（包括 gap/padding，排除绝对子项）。组合界面分别标为“素材原尺寸（扩展）”或“布局包围（扩展）”，与 `%c/%cm` 区分。

本轮改造 W/H 尺寸项；坐标偏移仍使用父级百分比＋像素，最小/最大限制仍使用像素字段。单位计算结果仍通过标准 Group/Cube/Texture 保存，未安装插件时可查看最后的成品。
